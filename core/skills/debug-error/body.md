# debug-error

에러·버그를 체계적으로 해결하는 절차다. 증상만 덮지 말고 근본 원인을 고친다.

## 절차

### 1. 증상 정확히 파악
- 전체 에러 메시지와 스택 트레이스를 그대로 확인한다.
- 어떤 동작에서, 어떤 조건에서 발생하는지 정리한다.
- 기대 동작과 실제 동작의 차이를 명확히 한다.

### 2. 재현
- 최소한의 조건으로 문제를 재현한다.
- 재현되지 않으면 환경·데이터·타이밍 차이를 먼저 확인한다.
- 재현 절차를 기록해 수정 후 검증에 재사용한다.

### 3. 원인 좁히기
- 스택 트레이스의 최초 발생 지점부터 역추적한다.
- 최근 변경(diff, 커밋)이 원인인지 먼저 의심한다.
- 이분 탐색으로 문제 구간을 좁힌다(코드 비활성화·로그·중단점).
- 추측을 사실처럼 단정하지 않고, 로그·값으로 가설을 검증한다.

### 4. 근본 원인 수정
- 증상이 아니라 원인을 고친다.
- 같은 원인으로 생길 수 있는 다른 케이스도 함께 점검한다.
- 기존 컨벤션을 따르고 범위를 넘어선 변경은 하지 않는다.

### 5. 검증 및 재발 방지
- 재현 절차로 문제가 사라졌는지 확인한다.
- 관련 검증(타입·린트·테스트)을 실행한다.
- 가능하면 이 버그를 잡는 회귀 테스트를 추가한다.
- 원인과 수정 내용을 요약한다. (이후 `implement-verify`로 마무리)

## 완료 기준
- 근본 원인을 설명할 수 있다.
- 재현되던 문제가 더 이상 발생하지 않는다.
- 재발 방지(테스트 등)를 고려했다.
- `resources/debug-checklist.md`를 점검했다.
