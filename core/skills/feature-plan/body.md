# feature-plan

기능 구현 전에 계획을 세우는 절차다. 계획 없이 바로 코드부터 작성하지 않는다.

## 절차

### 1. 요구사항 정리
- 무엇을, 왜 만드는지 한 문장으로 정리한다.
- 모호한 부분은 가정하지 말고 질문으로 확인한다.
- 완료 조건(무엇이 되면 끝인지)을 명확히 한다.

### 2. 현재 구조 파악
- 관련 컴포넌트, 훅, 상태, API, 타입을 먼저 찾아 확인한다.
- 재사용 가능한 기존 코드·패턴이 있는지 확인한다.
- 비슷한 기능이 이미 어떻게 구현돼 있는지 참고한다.

### 3. 영향 범위 분석
- 변경·추가할 파일을 나열한다.
- 라우팅, 상태 관리, API 계약, 타입 변경 등 파급 효과를 확인한다.
- 새 의존성이 필요하면 이유와 대안을 함께 정리한다.

### 4. 구현 계획 수립
- 작업을 독립적으로 검증 가능한 단계로 나눈다.
- 각 단계의 산출물과 검증 방법을 정한다.
- 로딩·오류·빈 상태 등 예외 케이스를 미리 목록화한다.
- 리스크와 미확정 사항을 명시한다.

### 5. 계획 공유
- `resources/plan-template.md` 형식으로 계획을 정리한다.
- 범위가 크거나 방향이 갈리는 지점은 착수 전 확인을 받는다.

## 완료 기준
- 요구사항, 영향 범위, 단계별 계획이 정리되어 있다.
- 미확정 사항과 리스크가 드러나 있다.
- `resources/checklist.md`의 항목을 점검했다.
