# implement-verify

계획을 코드로 옮기고, 동작을 검증까지 마치는 절차다. "구현 완료"는 검증까지 끝났을 때를 뜻한다.

## 절차

### 1. 구현 준비
- 구현할 단계와 대상 파일을 확인한다.
- 기존 컨벤션(네이밍·포맷·패턴)을 따른다.
- 요청 범위를 넘어선 변경은 하지 않는다.

### 2. 단계별 구현
- 계획의 단계를 하나씩 반영한다.
- 한 단계가 끝날 때마다 컴파일·타입이 깨지지 않는지 확인한다.
- TypeScript 오류를 `any`로 우회하지 않는다.
- 로딩·오류·빈 상태 등 예외 케이스를 함께 처리한다.

### 3. 검증
아래를 프로젝트에 있는 것 위주로 실행한다.
- 타입 체크 (예: `tsc --noEmit`)
- 린트 (예: `eslint`)
- 테스트 (예: `vitest` / `jest`) — 변경 관련 테스트 갱신·추가 포함
- 빌드 (필요 시)
- 실제 동작 확인(가능하면 화면·플로우를 직접 구동)

### 4. 결과 보고
- 실행한 검증 명령과 결과를 함께 보고한다.
- 실패가 있으면 사실과 출력을 그대로 전달한다. → 필요 시 `debug-error`로 전환한다.
- 검증을 건너뛴 항목이 있으면 건너뛴 사실을 명시한다.
- 무엇을, 왜 바꿨는지 요약한다.

## 완료 기준
- 계획한 변경이 모두 반영되었다.
- 검증 명령을 실행하고 결과를 보고했다.
- 실패나 미검증 항목을 숨기지 않고 드러냈다.
- `resources/verify-checklist.md`를 점검했다.
