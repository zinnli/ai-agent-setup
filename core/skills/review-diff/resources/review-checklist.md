# review-diff 리뷰 체크리스트

## 정확성
- [ ] 로직·경계 조건에 오류가 없다.
- [ ] 예외·에러 처리가 누락되지 않았다.
- [ ] 비동기(로딩/실패/경쟁 조건)를 올바르게 다룬다.

## 설계
- [ ] 책임이 적절히 분리돼 있다.
- [ ] 불필요한 복잡도·중복이 없다.
- [ ] 재사용 가능한 기존 코드를 무시하지 않았다.

## 프론트엔드
- [ ] 상태를 필요한 위치에 두었다.
- [ ] 훅 규칙과 의존성 배열이 올바르다.
- [ ] 리스트 key가 안정적이다.
- [ ] 접근성(시맨틱·레이블·키보드)을 고려했다.

## 타입
- [ ] `any`/무분별한 단언이 없다.
- [ ] 공개 함수·컴포넌트의 타입이 명시돼 있다.

## 테스트
- [ ] 변경에 대한 테스트가 있다.
- [ ] 사용자 관점의 동작을 검증한다.

## 리스크
- [ ] 시크릿·민감 정보 노출이 없다.
- [ ] 기존 동작 회귀 가능성을 확인했다.

## 컨벤션
- [ ] 네이밍·포맷·프로젝트 패턴과 일치한다.
