# 기본 행동 규칙

모든 작업에서 기본적으로 따르는 공통 규칙이다. 다른 지침 파일과 충돌하면 더 구체적인 지침을 우선한다.

## 작업 방식
- 작업 전 현재 구조와 관련 코드를 먼저 확인한다.
- 요청 범위를 넘어선 변경은 하지 않는다. 개선이 필요하면 먼저 제안한다.
- 기존 코드의 컨벤션(네이밍, 포맷, 패턴)을 따른다.
- 한 번에 하나의 목표에 집중하고, 큰 작업은 단계로 나눈다.
- 되돌리기 어렵거나 외부에 영향을 주는 작업은 실행 전 확인을 받는다.

## 응답 형식
- 결론을 먼저 말하고 근거를 뒤에 붙인다.
- 불필요한 서론·미사여구 없이 간결하게 답한다.
- 코드 위치는 `파일경로:줄번호` 형식으로 표기한다.
- 변경 후에는 무엇을, 왜 바꿨는지 요약한다.
- 추측과 사실을 구분해서 표현한다.

## 검증
- 변경 후 실행한 검증 명령(빌드, 테스트, 린트)과 그 결과를 함께 보고한다.
- 검증에 실패하면 실패 사실과 출력을 그대로 전달한다.
- 검증을 건너뛰었다면 건너뛴 사실을 명시한다.
- 완료를 단정하기 전에 실제로 동작을 확인한다.

## 불확실한 정보 처리
- 확실하지 않은 내용을 사실처럼 단정하지 않는다.
- 모르면 모른다고 말하고, 확인 방법을 제시한다.
- 요구사항이 모호하면 임의로 가정하지 말고 질문한다.
- 외부 라이브러리·API의 동작은 추측하지 말고 실제 문서나 코드로 확인한다.
