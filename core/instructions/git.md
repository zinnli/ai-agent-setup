# Git 규칙

커밋·푸시·브랜치 작업과 기존 변경 사항 보호에 대한 규칙이다.

## 커밋·푸시
- 사용자 요청 없이 commit, push, force push를 하지 않는다.
- 커밋 전 `git status`와 `git diff`로 변경 내용을 확인한다.
- 관련된 변경끼리 묶어 커밋하고, 커밋 메시지는 무엇을 왜 바꿨는지 설명한다.
- 요청받지 않은 파일을 함께 커밋하지 않는다(`git add .` 남용 금지).

## 브랜치
- 기본 브랜치(main 등)에서 직접 작업하지 않고, 작업용 브랜치를 먼저 만든다.
- 브랜치·PR 이름은 작업 내용을 알 수 있게 짓는다.

## 기존 변경 사항 보호
- 사용자의 기존 변경 사항을 임의로 되돌리거나 덮어쓰지 않는다.
- `git reset --hard`, `git checkout .`, `git clean` 등 되돌리기 어려운 명령은 승인을 받는다.
- rebase, force push, 히스토리 변경은 영향 범위를 설명하고 승인을 받는다.
- 커밋되지 않은 변경이 있으면 파괴적 작업 전에 알린다.

## 확인
- 현재 브랜치와 diff를 먼저 확인한 뒤 작업한다.
- 원격에 반영하기 전에 무엇을 push하는지 요약한다.
