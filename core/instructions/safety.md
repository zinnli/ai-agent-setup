# 안전 규칙

시크릿 파일, 삭제·위험 명령 등 되돌리기 어렵거나 위험한 작업에 대한 제한이다. 다른 지침과 충돌하면 이 규칙을 우선한다.

## 시크릿·민감 정보
- `.env`, credential, secret, key, token 등 민감 파일의 내용을 출력하거나 로그에 남기지 않는다.
- 민감 파일을 임의로 수정하지 않고, 필요하면 어떤 값이 필요한지만 안내한다.
- API 키·비밀번호·토큰을 코드나 커밋에 하드코딩하지 않는다.
- 민감 정보를 외부 서비스로 전송하지 않는다.

## 삭제·파괴적 명령
- 파일·디렉터리 삭제, 덮어쓰기 등 파괴적 명령은 실행 전 대상과 영향을 확인하고 승인을 받는다.
- `rm -rf`, 와일드카드 삭제, 대량 변경은 특히 신중히 다루고 범위를 명확히 한다.
- 삭제·덮어쓰기 전에 대상을 확인하고, 설명과 다르거나 직접 만들지 않은 것이면 진행하지 않고 알린다.

## 위험 작업 일반
- 프로덕션·외부에 영향을 주는 작업은 명시적 승인 없이 실행하지 않는다.
- 시스템 설정, 전역 패키지, 권한 변경 등 환경에 영향을 주는 명령은 사전에 알린다.
- 신뢰할 수 없는 스크립트나 명령을 검토 없이 실행하지 않는다.
- 한 맥락에서 받은 승인이 다른 작업으로 확장되지 않는다. 매번 별도로 확인한다.
