# 설치·업데이트·제거

모든 명령은 `--home=<dir>`로 대상 HOME을 바꿀 수 있다(테스트·미리보기). 지정하지 않으면 실제 HOME에 작업한다.

## install / update

`install`과 `update`는 같은 조정(reconcile) 엔진을 쓴다.

1. `core/` 로드·검증(오류 시 `--force` 없으면 중단).
2. 어댑터 렌더 → 전체 소유 파일과 병합 파일로 분리.
3. 각 파일 상태 판정:
   - `ADDED` 신규 · `UPDATED` 우리 파일 갱신 · `UNCHANGED` 동일 · `ADOPTED` 동일 내용 기존 파일 인수
   - `USER_MODIFIED` 사용자가 우리 관리 파일을 수정 → 보존·경고(`--force`로만 덮어씀)
   - `CONFLICT` 병합 대상의 소유 경로에 다른 값 존재 → 보존·경고(`--force`로만 덮어씀)
   - `REMOVED` 이전엔 관리했으나 더는 생성되지 않는 고아 → 제거(백업 있으면 복원)
4. 기존 파일은 최초 1회 백업 후 원자적 쓰기(temp + rename).
5. 매니페스트 저장.

## 매니페스트

`<installRoot>/.ai-agent-setup/manifest.json` — 도구별. 관리 파일(경로·`renderedHash`·백업·소스), 병합 항목(경로·전략·`format`·`managedPaths`·설치 값 해시/항목 서명·백업)을 기록한다. 비밀 값은 넣지 않는다.

## 백업

기존 사용자 파일을 처음 대체하기 전 `<installRoot>/.ai-agent-setup/backups/<타임스탬프>/<상대경로>`에 복사하고, 복사본 해시를 검증한 뒤에만 원본을 수정한다.

## 구조 병합

- **replace-keys** (MCP): 소유 경로에 우리 값을 설정. 다른 값이 있으면 충돌(이전 설치 값과 같으면 안전 갱신).
- **append-array** (hooks): 이벤트 배열에 우리 항목을 union. 래퍼 명령 서명으로 우리 항목을 식별해 재설치 시 중복 없이 교체하고, 사용자 항목은 보존.
- JSON·TOML 모두 파싱→객체 병합→직렬화. 잘못된 대상 파일은 건드리지 않고 오류로 보고.

## uninstall

- 관리 파일: 백업 있으면 복원, 없으면 삭제.
- 병합 항목: 설치 값과 일치하는 우리 항목만 제거(사용자 수정 값은 `--force` 없이는 보존). 우리가 만든 파일이 비면 삭제, 사용자 키가 남으면 유지.
- 매니페스트 삭제. 백업 디렉터리는 안전을 위해 남긴다.

## dry-run / force

- `--dry-run` 계획만 출력, 아무것도 쓰지 않음(매니페스트·백업 포함).
- `--force` 검증 오류·충돌·사용자 수정 파일을 덮어씀(덮어쓰기 전 백업).
